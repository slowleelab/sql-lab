# 预期结果 - bad.sql（AUTO_INCREMENT 在 TiDB 中的局限）

## TiDB v7.5.1

---

### AUTO_INCREMENT ID 分布

```
--- AUTO_INCREMENT ID 分布 ---
+----+----------------------+-----+
| id | name                 | val |
+----+----------------------+-----+
|  1 | auto_inc_a           | 100 |
|  2 | auto_inc_b           | 200 |
|  3 | auto_inc_c           | 300 |
|  4 | auto_inc_d           | 400 |
|  5 | auto_inc_e           | 500 |
|  6 | test1                |   1 |
|  7 | test2                |   2 |
|  8 | test3                |   3 |
|  9 | after_rollback       | 888 |  ← id=9，而不是 8（id=8 被回滚跳号）
+----+----------------------+-----+
```

**现象**：回滚事务的 ID 被永久丢弃，后续插入跳过该值。在高并发 + 频繁回滚的场景下，ID 空洞会快速累积。

---

### tidb_auto_increment_lock_mode

```
+-------------------------------------+-------+
| Variable_name                       | Value |
+-------------------------------------+-------+
| tidb_auto_increment_lock_mode       | 2     |
+-------------------------------------+-------+
```

| 值 | 模式 | 行为 |
|----|------|------|
| `0` | 无锁模式 | 不使用中心化锁，各 TiDB 实例自行分配，ID 跨实例不连续，但性能最高 |
| `1` | 连续锁模式 | 使用中心化锁保证连续性，跨实例 ID 递增，但有明显的锁竞争开销 |
| `2` | 无锁严格模式（默认） | 每个 statement 需要全局单调递增，但不能保证分配的 ID 严格连续 |

### AUTO_INCREMENT 写热点：SHOW TABLE REGIONS

```
AUTO_INCREMENT 表（写入集中在最后一个 Region）：
+-----------+-----------+--------+-----------+-----------------+
| REGION_ID | START_KEY | END_KEY| LEADER_ID | LEADER_STORE_ID |
+-----------+-----------+--------+-----------+-----------------+
|      1024 | t_1_     |        |      1025 |               1 |  ← 仅 1 个 Region
+-----------+-----------+--------+-----------+-----------------+
```

之所以只有一个 Region 是因为表刚创建且数据量少。随着写入持续增长，Region 会分裂，但每次分裂后新写入始终命中最后一个 Region——**热点随分裂迁移，不会消失**。

---

### AUTO_RANDOM 的 Region 分布（对比）

```
AUTO_RANDOM 表（写入打散到多个 Region）：
+-----------+-----------+--------+-----------+-----------------+
| REGION_ID | START_KEY | END_KEY| LEADER_ID | LEADER_STORE_ID |
+-----------+-----------+--------+-----------+-----------------+
|      1030 | t_3_00... |        |      1031 |               1 |
|      1032 | t_3_20... |        |      1033 |               2 |  ← 写入分散！
|      1034 | t_3_40... |        |      1035 |               3 |
+-----------+-----------+--------+-----------+-----------------+
```

Shard bits 将 ID 高位随机化，不同的 shard 前缀映射到不同的 Region，**写入压力被分散到多个 TiKV 节点**。

---

### 回滚导致 ID 跳号验证

```
SELECT id, name FROM t_auto_inc ORDER BY id DESC LIMIT 5;

+----+----------------------+
| id | name                 |
+----+----------------------+
|  9 | after_rollback       |  ← 跳过了 id=8
|  6 | test1                |
|  5 | auto_inc_e           |
|  4 | auto_inc_d           |
|  3 | auto_inc_c           |
+----+----------------------+
```

说明：BEGIN → INSERT（id=8）→ ROLLBACK → INSERT（id=9）。AUTO_INCREMENT 在事务开始时即分配 ID，回滚不会回收，导致空洞。
